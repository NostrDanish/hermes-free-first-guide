Three of the six provider commands this guide published in earlier editions did not install, and all three are replaced above. The bare `owner/repo` spec resolves for no repository at all, including ones whose `owner/repo/skills/<name>` form works, so it is an invalid spec rather than a per-repository quirk. This is a real usability cost of the scanner, not a documentation defect: readers of PayPerQ, Routstr, and the OpenCode client skill must clone and run or copy the skill, and the guide says so rather than publishing a command that fails.

Two commands were run with `--force` during measurement, because a CAUTION verdict needs an override to install at all. `--force` is **not** published: teaching readers to bypass the scanner would contradict the guide's own policy, and clone-and-run is the path the upstream repositories document.
