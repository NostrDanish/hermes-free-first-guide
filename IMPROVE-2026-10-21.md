# Improvement Deep-Dive — hermes-free-first-guide (PRIVATE) — 2026-10-21

Scope: main. Sources read: `README.md` (full), `requirements.txt`, directory listings (`scripts/`, `tests/`, `docs/`, `share-pack/`, `skills/`). Note: private repo — this file intentionally contains structure-level observations only, no content excerpts.

## Top recommendations (ranked, with effort S/M/L)

1. **Add CI for the test suite that already exists (S).** `tests/` has `test_setup_free_first.py`, `test_skill_contract.py`, `integration_setup.py` and the README documents `python3 -m unittest discover -s tests -v` — but there is no `.github/workflows/`. A 20-line workflow (Python 3.10–3.13 matrix, `pip install -r requirements.txt`, unittest discover, plus the offline skill-contract test) turns the guide's correctness claims into a gate that runs on every edit. The integration test (disposable homes, public catalog) can be a separate scheduled workflow since it touches the network.
2. **Harden the pip supply chain (S).** `requirements.txt` pins `Pillow==12.3.0` / `reportlab==5.0.1` with `==` but no hashes. Switch to `pip install --require-hashes` (generate via `pip-compile --generate-hashes` or `uv pip compile`) and add `pip-audit` to the new CI. This repo's whole premise is "give this to an AI to run on your machine" — its dependency chain should be maximally boring. (Latest-version freshness for Pillow/reportlab was not verified this session; pip-audit + a monthly CI re-resolve covers it.)
3. **Move generated binaries out of git (M).** `downloads/*.pdf/*.zip` and `share-pack/*.png/pdf` are committed build artifacts regenerated by `scripts/build_handbook.py` / `build_visuals.py` / `package_setup.py`. They bloat every clone and will drift from `docs/` sources. Options: GitHub Releases (works for private repos; links still access-gated), or a release workflow that builds and attaches artifacts on tag. Keep only `share-pack/TELEGRAM-CAPTION.txt`-style sources in-tree.

## Missing gates (CI/tests/protection)

- No CI at all (see #1). No lint (a `ruff check` step is nearly free for stdlib-only scripts). Private repo, so branch protection is lower-stakes, but a required status check still prevents self-foot-guns.
- The skill folder (`skills/hermes-free-first-setup/`) instructs AI agents to modify user config — the `test_skill_contract.py` contract test is exactly right; make CI run it so the script and SKILL.md can never silently disagree about flags (`--apply`, `--yes`, `--provider`).

## Quick wins (code/config)

- Font paths are hardcoded Linux absolutes (`/usr/share/fonts/...`) in the visual builder — move the three font constants to env vars with the current paths as defaults (README already documents the pain; make it fixable without editing code).
- `scripts/setup_free_first.py` — the README's dry-run-first + backup + rollback posture is good; add a `--version` flag and print it in every output so shared screenshots/logs are debuggable.
- `docs/VERIFICATION.md` dates catalog checks (20 Oct 2026) — add a tiny CI cron that fails when the newest verification date is >30 days old, so "recheck pricing" isn't honor-system.

## Hygiene

- README is exceptionally careful about scope, credential handling, and what the helper does NOT do — preserve that tone; it's the trust anchor of the repo.
- No LICENSE by design ("no additional public redistribution license" for a private repo) — fine; if any artifact is ever shared publicly, add an explicit license to the artifact itself, since forwarded PDFs lose repo context.
- `.gitattributes` present — confirm `*.pdf`/`*.zip` are marked `binary` (or `-text`) so no accidental line-ending mangling.
- Consider a `SECURITY.md`-style note even privately: "if you find a credential committed here, rotate and purge history" — cheap insurance for a credentials-adjacent repo.
